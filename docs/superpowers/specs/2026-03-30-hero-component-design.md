# Hero 组件设计

## 背景

当前项目已经完成 React + TypeScript + Vite + Tailwind CSS 的基础初始化，并搭好了作品集首页的占位结构。本次变更聚焦于首页 Hero 组件的首轮视觉升级，使其从“工程占位块”提升为更接近真实作品集首页的头部展示区域。

## 目标

- 创建一个包含大标题、简介和字母头像的 Hero 组件。
- 使用 Tailwind CSS 实现深色主题视觉。
- 在标题和背景中加入适度的渐变效果，提升首页辨识度。
- 保持组件结构清晰，为后续继续填充真实个人信息和动效预留空间。

## 非目标

- 当前不接入真实头像图片资源。
- 当前不添加 CTA 按钮、复杂滚动动画或 Framer Motion 动效。
- 当前不修改 About、Projects、Contact 等其他区块的结构与文案。
- 当前不接入真实个人资料、项目数据或社交账号信息。

## 推荐方案

采用“左侧文案，右侧字母头像卡片”的双栏 Hero 布局。左侧负责建立第一眼的信息层级，右侧用带发光边缘的圆形字母头像补足视觉重心。这种方案既符合作品集站点常见的阅读习惯，也便于后续逐步替换成真实内容，而不需要重新组织整体结构。

## 备选方案

### 1. 左文案右头像卡片

推荐方案。信息结构稳定、实现成本适中、移动端改造也自然，适合作为当前站点的第一版 Hero。

### 2. 上方超大标题，下方悬浮头像

更偏视觉海报感，首屏冲击力更强，但简介的可读性和与下方区块的衔接会稍弱。

### 3. 中轴对称标题，头像嵌入标题区

辨识度高，但更依赖精细排版控制，容易超出“简洁现代”的设计要求。

## 布局设计

- Hero 保持两栏布局，在桌面端左文案右头像，移动端折叠为单列。
- 左侧包含：
  - 小型标签，用于说明身份或站点类型。
  - 主标题，使用 2 到 3 行的大字号排版。
  - 简介段落，说明个人定位和网站内容方向。
- 右侧包含：
  - 一个圆形字母头像容器。
  - 字母头像使用 `EW` 作为默认内容。
  - 头像容器采用柔和边框、内层渐变和外层发光。

## 视觉风格

- 维持全站深色主题，以 `#0a0a0a` 为基础背景。
- Hero 区域叠加深蓝黑渐变，让首屏有更强的层次感。
- 标题中仅高亮一段关键词，使用蓝青到紫蓝的渐变文字。
- 简介文字使用较低对比度的灰白色，以突出标题层级。
- 背景增加两层轻微径向光斑，一层偏左上，一层偏右侧，服务于标题与头像的视觉聚焦。

## 响应式策略

- 桌面端使用双栏布局，保证标题区和头像区视觉平衡。
- 平板及移动端改为单列堆叠，优先保证标题和简介可读性。
- 在小屏幕下适当缩小标题字号与头像尺寸，避免首屏内容过满。

## 组件边界

- 主要修改 `src/components/Hero.tsx`。
- 仅在必要时补充少量全局样式，不扩大到其他区块重构。
- 不新增图片资源，不修改数据文件结构。
- 组件内部可以保留少量注释，用于说明当前为首屏骨架实现。

## 验证方式

- 运行 `npm run build`，确认 Hero 组件更新后构建通过。
- 运行 `npm run lint`，确认 Tailwind 类名和组件代码无 ESLint 报错。
- 手动检查组件结构是否包含大标题、简介和字母头像三项核心内容。

## 实施说明

- 当前版本的 Hero 应优先建立视觉方向，而不是一次性做完最终交互。
- 字母头像方案是为了避免阻塞在资源准备阶段，后续可以无缝替换为真实头像图片。
- 本次完成后，Hero 将从“工程初始化占位”升级为“可继续迭代的首页核心展示区”。
