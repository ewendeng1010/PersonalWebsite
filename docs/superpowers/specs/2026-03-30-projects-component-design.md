# Projects 组件设计

## 背景

当前作品集站点已经完成基础工程初始化，并且 Hero 组件已经具备较完整的视觉方向。相比之下，Projects 区块仍然停留在较轻的占位展示状态，虽然已经有标题、描述和技术栈标签，但卡片结构和截图区域还不足以承载“作品展示”这一核心职责。

本次变更聚焦于 Projects 组件的首轮升级：将现有项目列表改造成更完整的项目卡片展示区，使每个项目具备截图区域、标题、描述和技术栈标签，并与当前深色主题保持一致。

## 目标

- 创建更完整的 Projects 组件项目卡片列表。
- 每个项目卡片都包含截图区域、标题、描述和技术栈标签。
- 使用深色主题和细腻的渐变、边框、阴影效果，保持和 Hero 一致的视觉语言。
- 保持结构清晰，便于后续无缝替换为真实截图和真实项目内容。

## 非目标

- 当前不接入真实项目截图资源。
- 当前不添加筛选、分类、弹窗详情页或轮播交互。
- 当前不修改项目数据结构为更复杂的 schema。
- 当前不改动 About、Contact、Footer 等其他区块。

## 推荐方案

采用“左侧截图，右侧信息”的分栏项目卡片布局。截图和内容并列，既能突出作品感，又能保留清晰的信息层级。这种方案特别适合作品集首页中的精选项目展示，也更容易在未来扩展为多项目列表。

## 备选方案

### 1. 编辑感展示卡

截图权重更高，视觉冲击强，但信息组织略偏海报化，和当前项目列表的扩展性相比稍弱。

### 2. 分栏信息卡

推荐方案。截图和信息区权重更均衡，阅读顺序自然，既适合作品展示，也适合作为后续案例列表的统一卡片模式。

### 3. 画廊式纵向卡片

结构更整齐、适合大量项目铺陈，但与当前 Hero 的气质相比辨识度略弱，卡片内部的叙事张力也较少。

## 卡片结构

- Projects 区块继续使用网格列表展示多个项目。
- 单张卡片采用左右分栏布局：
  - 左侧为截图展示区域。
  - 右侧为信息区。
- 信息区包含：
  - 项目标题
  - 项目描述
  - 技术栈标签组
  - 项目链接
- 在移动端，卡片应自然折叠为上下结构，优先保证截图和标题的可读性。

## 截图区域设计

- 当前阶段不使用真实截图，因此截图区域应采用高质感占位图块。
- 占位图块不再使用简单虚线框，而是模拟“产品预览面板”效果：
  - 深色渐变背景
  - 细边框和内层描边
  - 柔和高光或局部色彩层
  - 少量几何区块，暗示界面结构
- 这样做的目的是在没有真实图片资源时，仍让卡片保持足够的完成度和展示感。

## 视觉风格

- 整体延续深色主题，以蓝黑、灰黑和青蓝高亮作为主要视觉语言。
- 卡片本体使用轻微透明背景、柔和描边和较深阴影，营造悬浮感。
- 标题使用高对比度白色。
- 描述使用低一档灰白色，保证层级。
- 技术栈标签采用青蓝系半透明胶囊样式，与 Hero 的渐变高亮形成呼应。
- 卡片 hover 时只做轻微抬升、边框提亮和截图区域光感增强，不做夸张动画。

## 数据边界

- 保持当前 `src/data/projects.ts` 的结构不变。
- 继续使用现有字段：
  - `name`
  - `description`
  - `techStack`
  - `image`
  - `link`
- 当 `image` 为空时，组件自动渲染占位截图块，而不是依赖外部图片。

## 响应式策略

- 桌面端使用左右分栏卡片，增强展示感。
- 平板和移动端切换为上下堆叠布局。
- 小屏幕下适当收紧内边距、标签间距和描述宽度，避免视觉过重。

## 组件边界

- 主要修改 `src/components/Projects.tsx`。
- 如有必要，可微调 `src/data/projects.ts` 中的占位内容，但不扩展字段结构。
- 不新增复杂状态逻辑，不引入新的依赖库。
- 保持组件为纯展示型实现。

## 验证方式

- 运行 `npm run build`，确认组件更新后可以顺利构建。
- 运行 `npm run lint`，确认无 ESLint 报错。
- 检查每张项目卡片是否都包含截图区域、标题、描述和技术栈标签。

## 实施说明

- 本次变更的重点不是“真实项目数据”，而是先把项目展示的视觉骨架建立起来。
- 当前的高质感占位截图块是过渡方案，但应具备足够的完成度，避免组件再次退回简单占位状态。
- 本次完成后，Projects 组件应从“信息列表”提升为“作品展示区”的角色。
